# 工作流节点编辑器改进设计规格

日期：2026-08-20  
状态：已确认，待实施

## 1. 目标

改进工作流画板中的条件节点、节点选择和属性编辑、字段契约编辑及结构复制粘贴体验。保持现有 Vue Flow 画布、Pinia 草稿状态和后端图协议兼容，不引入新的工作流存储接口。

## 2. 范围与边界

### 2.1 本次实现

- 条件节点支持为空、不为空、等于、不等于、大于、小于、大于等于、小于等于、包含。
- 条件节点支持多条判断，使用“且”或“或”统一组合，按列表顺序短路计算。
- 条件节点固定只有两个出口；出口内部 ID 保持稳定，显示名称可编辑，默认显示“满足”和“不满足”。
- 连线从满足/不满足对应句柄创建，并在连线上显示当前出口名称。
- 画布点击节点后高亮描边；侧栏标题显示节点类型和节点名称。
- 节点名称默认以文本呈现，点击后切换为可编辑输入框，回车或失焦保存，Esc 取消。
- 输入、规则、LLM、输出节点支持输入字段和输出字段列表的新增、删除、类型、必填设置。
- 字段下拉联想目录合并数据准备字段和当前工作流其他节点输出字段，并标注来源、去重且排除当前节点自身输出。
- 结构复制和结构粘贴移动到节点侧栏底部的可折叠“结构工具”区域，默认收起。
- 保留现有节点 JSON 脱敏、校验、预览和导入为新节点能力。

### 2.2 本次不实现

- 条件节点动态增加第三个或更多出口。
- 多分支规则列表（例如高风险/中风险/低风险）的执行语义。
- 同一条件节点同时命中多条后续路径。
- 新增工作流图存储接口或数据库迁移。
- 改造非输入、规则、LLM、输出节点的专用表单结构。

## 3. 条件节点设计

### 3.1 前端配置模型

条件节点配置新增稳定结构：

```json
{
  "operator": "and",
  "operands": [
    {
      "left": "facts.her2_status",
      "operator": "not_empty",
      "right": null
    },
    {
      "left": "facts.age",
      "operator": "lt",
      "right": 70
    }
  ],
  "true_port": "satisfied",
  "false_port": "unsatisfied",
  "true_label": "满足",
  "false_label": "不满足",
  "missing_strategy": "false"
}
```

`true_port` 和 `false_port` 是稳定的内部端口 ID，用户修改 `true_label` 和 `false_label` 时不改变已有边的端口引用。已有单条件配置（`operator/left/right` 或 `left_path/right_value`）继续读取，并在首次编辑时转换为 `operands` 条件组；已有 `true_port/false_port` 和边标签继续保留。该结构直接复用运行时已有的 `and/or + operands` 递归条件协议，只新增 `not_empty` 和缺失策略行为。

支持的运算符及中文显示：

| ID | 显示名称 | 比较值 |
| --- | --- | --- |
| `empty` | 为空 | 不需要 |
| `not_empty` | 不为空 | 不需要 |
| `eq` | 等于 | 需要 |
| `neq` | 不等于 | 需要 |
| `gt` | 大于 | 需要 |
| `lt` | 小于 | 需要 |
| `gte` | 大于等于 | 需要 |
| `lte` | 小于等于 | 需要 |
| `contains` | 包含 | 需要 |

条件表单按规则顺序显示，每行支持字段选择/手动输入、运算符、比较值和删除；底部支持新增条件。组合方式在列表上方选择“且/或”。

### 3.2 执行语义

- `and`：依次计算条件，首个 `false` 即判定整体不满足；没有 false 时，若存在 unknown 则按缺失策略处理，否则满足。
- `or`：依次计算条件，首个 `true` 即判定整体满足；没有 true 时，若存在 unknown 则按缺失策略处理，否则不满足。
- `empty` 将已存在字段中的 `null`、空字符串、空数组、空对象视为空；`not_empty` 为其反向判断。字段路径不存在时两者均返回 unknown，并交由缺失策略处理。
- 数值与字符串比较沿用运行时安全比较，类型错误返回 unknown，不抛出原始异常。
- `missing_strategy` 支持按不满足、标记待补充、终止运行；默认按不满足。“标记待补充”选择不满足出口并在节点结果中保留 `needs_review` 标记，“终止运行”抛出稳定的条件配置错误。
- 条件结果只选择 `true_port` 或 `false_port`，不会同时选择两条路径。

### 3.3 画布表现

条件节点左侧保留输入句柄，右侧渲染两个带稳定 ID 的 source handle：`satisfied` 与 `unsatisfied`。句柄旁显示当前出口名称。新建边时根据 source handle 自动写入后端规范的 `source_port` 和 `branch_label`；已有未命名条件边根据 source port 回填当前出口名称。普通节点继续使用单一 `input/output` 句柄。

## 4. 节点选择与侧栏

- `WorkflowCanvas` 维护选中节点 ID，并把选中状态传递给 Vue Flow 节点数据或节点 class。
- 选中节点使用高亮描边，颜色与现有 teal 主题一致；未选中节点保持原有边框。
- `NodeInspector` 标题显示中文节点类型和节点名称，例如“条件 · HER2 判断”，不再显示统一“节点属性”。
- 名称展示区可点击进入编辑态。输入框获得焦点；Enter/blur 提交非空名称，Escape 恢复编辑前名称；空名称不提交并保留编辑态。
- 节点删除操作保留在标题区。

## 5. 字段契约编辑

### 5.1 字段结构

输入和输出字段保存于节点 `config.input_fields` 与 `config.output_fields`，每个字段至少包含：

```json
{
  "name": "age",
  "path": "facts.age",
  "type": "number",
  "required": true
}
```

字段编辑器支持字段新增、删除、名称/路径编辑、类型选择和必填切换。旧的 `inputs`、`transfer_fields`、`output_alias` 等配置不被删除；运行时仍可回退读取旧配置。

### 5.2 联想目录

目录由两类来源合并：

- 数据准备分组中的字段别名和路径，来源标记为“数据准备”。
- 当前图中其他节点的 `config.output_fields`，来源标记为节点名称；兼容旧的 `output_alias` 等单字段输出配置。

按字段引用路径去重，保留更具体的来源信息；当前节点自身输出不进入其输入字段候选。字段输入允许选择目录项，也允许直接填写未登记路径。

## 6. 结构工具

在 `NodeInspector` 侧栏底部增加默认收起的折叠区“结构工具”。展开后显示：

- 复制节点 JSON：调用现有脱敏序列化和系统剪贴板。
- 粘贴节点 JSON：文本框、校验、问题提示、导入预览和“导入为新节点”。

折叠状态仅为当前组件本地 UI 状态，不写入工作流草稿。

## 7. 组件与数据流

- `WorkflowEditorView` 继续作为图状态唯一协调者，负责传入图、字段目录、选中节点及节点更新。
- `WorkflowCanvas` 负责 Vue Flow 节点/边映射、条件多句柄渲染、边标签和选择事件。
- `WorkflowNode` 负责节点内部标题、摘要和动态句柄，不直接修改图数据。
- `NodeInspector` 负责标题、名称编辑、删除和结构工具折叠，并通过事件提交节点更新。
- `NodeSemanticForm` 负责节点专用配置；条件配置和字段契约列表作为可复用子组件或局部组件实现。
- `useGraphAdapter` 负责端口/边标签兼容映射；`useNodeClipboard` 保持现有脱敏边界。
- `backend/app/runtime/conditions.py` 扩展规则列表、`not_empty` 和缺失策略；图协议仍使用现有 `input_ports/output_ports` 与边端口字段。

画布内部继续使用 Vue Flow 的 `sourceHandle/targetHandle/label`，保存到草稿时统一转换为后端规范：节点端口保存为字符串 ID 数组，边保存为 `source_port/target_port/kind/branch_label`。加载时兼容当前前端草稿中的端口对象以及 `source_handle/target_handle/label` 字段，但再次保存时写回规范格式，避免发布阶段协议不匹配。

## 8. 错误处理与兼容性

- 条件缺少字段、比较值类型不匹配或路径不存在时，不泄露原始异常；按 unknown 和缺失策略处理。
- 无效条件行不阻止用户暂存草稿；表单就地提示缺失字段或比较值，运行时对无法求值的条件按 unknown 和缺失策略处理。
- 条件节点缺少端口时，前端加载时补齐稳定的 `satisfied/unsatisfied` 端口；已有边保持原 source handle，并在可推断时补充标签。
- 字段目录为空时仍允许手动输入；字段列表删除最后一项后显示空状态和新增按钮。
- 粘贴结构继续过滤敏感字段，校验失败不得修改当前图。

## 9. 测试与验收

### 9.1 前端单元测试

- 条件运算符列表包含九种要求的运算符，比较值在空/不为空时隐或禁用。
- 条件列表支持新增、删除、且/或切换，并正确序列化为 `operator + operands`。
- 条件节点渲染两个稳定出口句柄，修改标签后边标签同步更新。
- 普通节点句柄行为不回归；旧条件图能正常映射。
- 旧的 `source_handle/target_handle/label` 边可读取，再次保存后转换为 `source_port/target_port/branch_label`。
- 节点选择高亮侧栏标题、名称点击编辑的 Enter/blur/Escape 行为。
- 字段目录合并、去重、来源标记和排除当前节点。
- 结构工具默认折叠，展开后保留复制/粘贴校验流程。

### 9.2 后端单元测试

- `empty`、`not_empty`、`eq`、`neq`、`gt`、`lt`、`gte`、`lte`、`contains` 均有正反例。
- 多条件 `and/or` 的短路和 unknown 缺失策略行为。
- 条件结果只选择满足或不满足端口。
- 旧单条件配置继续兼容。

### 9.3 验收

- 在 1440px 和 390px 宽度下，两个条件出口、边标签、字段列表和侧栏操作无重叠或截断。
- `npm run test:unit`、`npm run build` 通过；涉及运行时的后端测试通过。
- 从现有草稿加载、编辑、保存、重新加载后，条件端口名称、边标签和字段契约保持一致。
