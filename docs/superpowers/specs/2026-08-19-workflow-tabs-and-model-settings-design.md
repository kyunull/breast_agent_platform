# 工作流页签与模型服务配置设计规格

日期：2026-08-19
状态：已确认，待实施

## 1. 目标

将工作流编辑区改为三个可直接访问的页签工作区，使用户能在接入数据、工作流画板和在线测试之间快速切换。为管理员补充统一的系统配置入口，以中文表单维护 OpenAI 兼容 LLM 服务，而不是编辑技术配置 JSON。

本设计沿用已有工作流草稿、Profile、权限、模型网关和审计能力，不引入新的 LLM 协议或多租户配置中心。

## 2. 范围与边界

### 2.1 本次实现

- 每个工作流提供“接入数据”“工作流画板”“在线测试”三个顶部页签。
- 页签由 URL 驱动，支持刷新、浏览器前进后退和直接访问。
- 数据配置从现有画板编辑页中拆出，保留原有 JSON 路径选择、分组、字段配置和提取预览能力。
- 管理员侧边栏将“配置档案管理”调整为“系统配置”。
- 系统配置页将模型 Profile 与知识库 Profile 作为两类配置项；模型 Profile 使用表单维护 OpenAI 兼容服务参数。
- 管理员可测试尚未保存或已保存的模型连接；测试请求不包含患者数据和真实密钥。
- 普通医学用户只能选择已启用、已开放的模型 Profile，不能读取或提交技术参数。

### 2.2 本次不实现

- Azure、Anthropic、Gemini 等非 OpenAI Chat Completions 协议适配。
- 在浏览器、数据库、草稿、日志或审计详情中保存真实 API Key。
- 用户、角色、安全白名单等其他系统配置页面。
- 模型健康状态、用量计费和复杂连接监控的持久化仪表盘。

## 3. 工作流页签

### 3.1 路由

| 页签 | 路由 | 页面职责 |
| --- | --- | --- |
| 接入数据 | `/workflows/:id/data` | 配置全量 JSON 的提取分组、字段、类型和样例预览。 |
| 工作流画板 | `/workflows/:id/edit` | 配置节点、连线、节点属性、保存与发布。 |
| 在线测试 | `/workflows/:id/test` | 选择草稿或发布版本，输入脱敏样例并查看输出、追踪与证据。 |

保留 `/workflows/:id/edit` 作为画板路由，避免已有书签失效。原有测试路由保持不变。`/workflows/:id/data` 为新增路由。

### 3.2 布局与交互

- 在工作流名称和说明下方、具体工作区内容上方放置局部页签栏，不替代应用左侧主导航。
- 页签依次显示“接入数据”“工作流画板”“在线测试”，使用当前路由作为唯一激活来源。
- 页签栏显示当前草稿版本和保存状态；保存、发布等跨页操作保持在共同的工作流上下文头部。
- 切换页签只改变路由，不清空 Pinia 中当前草稿。用户编辑的 `graph` 与 `extraction` 需在切换后立即反映在另一页签中。
- 重新加载或直接打开某个页签时从后端加载同一草稿；未保存变更采用现有 dirty 状态提示，不能被静默覆盖。
- 桌面端页签与示意图一致采用横向文本导航和底部激活线；窄屏时允许横向滚动，点击目标至少保留 40px 高度。

### 3.3 组件边界

- 新增工作流上下文头部/页签组件，唯一负责标题、草稿状态、全局操作和页签导航。
- `WorkflowDataView` 只负责数据接入，复用现有 `DataPreparation` 组件和工作流 store。
- `WorkflowEditorView` 只负责画板与节点属性，不再在画板下方渲染数据接入面板。
- `WorkflowTestView` 使用同一页签组件并保留其已有的运行、追踪和证据交互。

## 4. 管理员系统配置

### 4.1 导航与权限

- 仅 `admin_developer` 在左侧主导航中看到“系统配置”。
- 系统配置页保留管理员路由守卫；普通用户直接访问也必须被重定向到工作流列表，后端写接口继续返回 `403`。
- 系统配置页提供“模型服务”和“知识库服务”两个页内标签。第一期不添加空的用户、安全策略等标签。

### 4.2 模型服务列表

列表显示配置名称、说明、模型标识、服务地址摘要、对医学用户开放状态、启用状态和编辑操作。密钥引用只显示变量名，绝不显示其解析值。

列表中的“测试连接”是图标操作，结果在当前行或对话框中显示：成功时显示实际响应模型和耗时；失败时显示可操作的中文原因。

### 4.3 模型服务表单

模型 Profile 表单字段如下：

| 分组 | 字段 | 规则 |
| --- | --- | --- |
| 基本信息 | 名称、说明、启用、对医学用户开放 | 名称必填且唯一。停用后不可作为新的运行选择。 |
| 连接 | 服务类型、服务地址、模型标识、密钥环境变量引用 | 服务类型固定为“OpenAI 兼容接口”；地址和模型必填；密钥引用可为空以支持无需鉴权的本地服务。 |
| 运行参数 | 温度、Top P、最大输出 Token、超时、重试次数 | 仅管理员可见和编辑，按后端现有参数范围校验。 |
| 医学侧说明 | 展示名称、临床适用范围、支持任务、输出风格 | 保存至 `medical_options`，普通用户仅接收这些语义化字段。 |

知识库服务沿用现有 Profile 能力；本次可同步将其 JSON 表单整理为已有字段的中文表单，但不得扩展到新的知识库协议。

### 4.4 密钥与环境变量

- 浏览器只提交 `api_key_ref`，例如 `DASHSCOPE_API_KEY_REF`，不提供真实 API Key 输入框。
- 后端仅解析服务器进程环境变量。部署者可设置 `DASHSCOPE_API_KEY=实际密钥`，Profile 中引用 `DASHSCOPE_API_KEY_REF`；也可将 `DASHSCOPE_API_KEY_REF` 设置为另一个环境变量名称。
- 前后端错误、列表、编辑回填、测试响应和审计元数据均不得包含真实密钥。
- 后端继续拒绝 `api_key`、`token`、`password` 等原始密钥字段，并校验引用名符合大写 `*_REF` 格式。

### 4.5 连接测试接口

新增仅管理员可调用的模型连接测试接口：

`POST /api/v1/model-profiles/test`

请求体复用待保存 Profile 的公开字段和 `technical_config`，仅接受 OpenAI 兼容配置。接口以固定、无患者信息的短消息调用 `{base_url}/chat/completions`，并返回：

```json
{
  "ok": true,
  "model": "实际响应模型",
  "latency_ms": 320
}
```

失败时返回统一错误结构，不返回授权头、请求体或供应商原始敏感信息。接口不持久化测试请求；配置的创建、更新和启停继续记录审计日志。

## 5. 数据流与兼容性

```text
管理员配置模型 Profile
  -> technical_config 保存 base_url/model/api_key_ref/运行参数
  -> LLM 节点引用 model_profile_ref
  -> 运行时模型网关解析服务器环境变量
  -> OpenAI 兼容 Chat Completions 服务
```

现有 `GET/POST/PATCH /api/v1/model-profiles` 和 Profile 数据库表继续作为配置的唯一来源，不需要数据库迁移。前端仅将 JSON 文本改为受控表单对象后仍提交同一 `ProfileCreate`/`ProfilePatch` 契约。

## 6. 错误处理

- 未填写服务地址或模型标识时禁止提交或测试，并定位到对应字段。
- 密钥引用不符合 `*_REF` 格式时显示“密钥环境变量引用必须为大写 *_REF 名称”。
- 环境变量未解析时显示“服务器未配置该密钥引用”，不显示变量值。
- 网络错误、鉴权失败、超时和模型响应不合法使用稳定错误码及中文说明；测试页面可重试。
- 切换工作流页签加载失败时保留当前草稿显示，并提供重试，不把空数据写回 store。

## 7. 测试与验收

### 7.1 前端单元测试

- 页签根据当前路由正确高亮，并生成三个工作流 URL。
- 数据页更新 `extraction` 后切换到画板和测试页，store 中草稿不丢失。
- 管理员模型表单将字段正确序列化为 `technical_config` 和 `medical_options`。
- 普通用户不显示系统配置入口，也不渲染技术参数和密钥引用。

### 7.2 后端测试

- 普通用户调用模型 Profile 创建、更新和连接测试均返回 `403`。
- 原始 `api_key` 被拒绝，合法 `api_key_ref` 被接受。
- 连接测试通过 Mock Chat Completions 验证 URL、模型和非敏感固定消息；响应和错误中不含密钥。
- 已停用或未开放 Profile 的既有运行权限保持现有规则。

### 7.3 端到端测试

- 管理员打开工作流画板，依次切换接入数据、画板、在线测试，URL、激活页签和草稿状态均正确。
- 在接入数据页修改字段配置，切到画板后保存草稿，重新加载数据页仍显示该配置。
- 管理员创建 OpenAI 兼容模型服务并执行连接测试；普通用户登录后只能选择已开放且已启用的 Profile。
- 1440px 和 390px 宽度下页签、模型表单和操作按钮无重叠或截断。
